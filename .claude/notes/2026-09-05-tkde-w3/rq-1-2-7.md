## 2. Understanding and plan

**Restatement of the task in my own words:** Build three experiment runners
(RQ1 addressing, RQ2 well-posedness, RQ7 envelope) and their analyzers against
the frozen corpora and the shipped encoder, exactly as `DESIGN.md` §2/§3/§8
specify; wrap them in Picasso launcher/worker pairs that respect the cluster's
measured rules; prove them locally; deploy to a private remote checkout; run one
short cluster smoke per research question; then launch the campaign and verify
its first real task lands rows on the permanent filesystem.

**Approach chosen:** one module per research question with the same skeleton —
a deterministic `Unit` enumeration, an idempotent per-unit row file, a
`--shard i/N` selector, and a `--start-cutoff-epoch` that refuses to *start* a
late unit (never to shorten one). One `budget.py` holds the only mechanism that
bounds the C++ pointer arm and the oracles: a forked child killed with SIGKILL.
Analyzers are pure readers over `rows_*__*.csv` and are written to run on
partial output.

**Alternatives considered and rejected:**
- *One row file per shard rather than per unit* — rejected: a shard is bundled
  into a task with a wall-clock, and a per-shard file loses every unit of a task
  that TIMEOUTs. Per-unit files bound the loss to one unit and make the resume
  pass exact. File counts stay small (a few hundred), well inside HOME's 35k.
- *In-process `SIGALRM` or the oracle's own `timeout=` argument* — rejected on
  the measurement in `COMPETITOR_AUDIT.md` §1: the canonical string never
  returns to the interpreter, so the Python handler never runs, and even
  `SIGTERM` does not end it.
- *Computing the design's `rows_m0` and `rows_yield` inside the runner* —
  rejected: both are collection-wide aggregates (a partition, a median) that a
  shard seeing a slice of the members cannot compute. The runners emit the
  per-member ingredients and the analyzers reduce them, which also keeps the
  reduction reproducible from persisted rows.
- *Calling each arm's `pairwise(H1, H2)` per pair in RQ1* — rejected as pure
  waste: every RQ1 arm's `pairwise` is literally
  `Levenshtein(fingerprint(H1), fingerprint(H2))` (read in each arm's source),
  so the word is computed once per member and compared as a symbol sequence.
- *One RQ2 array under the matrices dependency* — rejected: only the census
  units need the matrices, and making the oracle and bipartite units wait for a
  job that starts hours later wastes the queue slot. Two arrays, split by
  `--kinds`.

**Plan as executed:**
1. Read `DESIGN.md` §1/§2/§3/§8/§9/§10, `CODE_PLAN.md`, `slurm/tkde/README.md`,
   `common.sh`, `COMPETITOR_AUDIT.md`, and the signatures of every library
   function I call.
2. Measure the pointer arm's cost profile on 40 members of each corpus, and size
   every block count from that rather than from a guess.
3. Write `budget.py`, then `rq1.py`, `rq7.py`, `rq2.py`, then the three
   analyzers, smoking each as soon as it existed.
4. Write the six SLURM scripts against the README skeleton.
5. Write the test file; run ruff, the tests, and the three local smokes.
6. Deploy, `sbatch --test-only`, one cluster smoke per RQ, then the campaign.

**Deviations from the plan:** two.
- The prompt's block sizing assumed a roughly uniform pointer cost. The measured
  profile is bimodal (median 1-2 ms, mean 2-6 s driven by a ~7 % censored tail),
  so the first configuration I wrote was re-derived from the measurement before
  anything was submitted.
- The RQ2 worker's `matrices/` symlink had to be made conditional: in
  `--smoke` mode the configuration puts `ndc_classes` in
  `census_own_collections` over a 20-member subset, which through the symlink
  would have written a 20x20 matrix over the real `ndc_classes` cache that the
  shared matrices job (2213202) was building at that moment.

| `TestBudget::test_a_non_positive_budget_is_refused` | a zero/negative budget raises | a mis-typed config would otherwise censor everything and produce an all-null campaign |
| `TestSymbolDistance::test_the_alphabet_is_shared_across_the_sequences` | both sequences encode against one alphabet | per-sequence alphabets map different symbols to the same character and report distance 0 -- a silent all-zeros distance matrix |
| `TestBlockSlice` (3) | blocks partition the range exactly and differ by at most one | an off-by-one drops members from the corpus with no error |
| `TestShardParsing` (3) | `i/N` parsing and its refusals | a bad `--shard` must fail loudly, not compute the wrong slice |
| `TestUnitEnumeration` (5) | determinism, unique ids, `--kinds` filtering, no shell metacharacters in ids, shards partition the units | a non-deterministic enumeration breaks idempotence; a duplicate id makes two units overwrite one file |
| `TestM0Reduction` (3) | false merges/splits counted separately, complete invariants score zero, censored members excluded | this arithmetic *is* the RQ1 M0 claim; a wrong pair count reads as a defect in the representation |
| `TestCensusCounts` (4) | zero-distance pairs across classes counted, within-class zeros not, tolerance load-bearing | an equality test instead of `< 1e-9` reports zero false merges for NetLSD, whose isomorphic pairs land at ~1e-14 |
| `TestZeroPredicate`, `TestBuckets` (8) | the tolerance and the six size buckets | boundary errors here shift whole table rows |
| `TestAnalyzersOnEmptyTrees` (4) | all three analyzers run on an empty tree; RQ2 reports the certificate section `pending`; only the merged certificate file is read | the analyzers run mid-campaign; and globbing `parts/` as well as the merged file would double every certificate rate |
| `TestSmokeEndToEnd` (4) | each runner's `--smoke` then its analyzer on the real corpora; a rerun rewrites no row file | proves idempotence on the real path, which is what the SLURM resume pass depends on |

**Coverage of the behaviour that matters:** the budget's kill path, every
aggregate reduction the analyzers own, unit/shard bookkeeping, and one real
end-to-end pass per runner. **Not tested:** the SLURM scripts beyond `bash -n`
(they are exercised by the cluster smoke jobs instead); the census's cached-matrix
reader against a real shared cache (it is exercised by the census array, which is
queued behind the matrices job); and the statistical estimators themselves, which
are `experiments/tkde/stats.py`'s own tests, not mine.

## 7. Decisions, assumptions, open questions

**Decisions with a real trade-off:**
- *One shard per unit, bundled by the launcher.* Costs a few hundred small files
  under HOME; buys a resume pass that is exact to the unit and a start-cutoff
  that can defer without wasting a partial computation.
- *Uniform process-level budget for every RQ2 arm, not only the uninterruptible
  ones.* Costs one fork per pair (milliseconds); buys the impossibility of
  exempting the wrong arm as the arm list grows.
- *`rows_m0` and `rows_yield` are written by the analyzer.* Costs a departure
  from "the runner writes the design's tables"; buys correct collection-wide
  aggregates under sharding, which the alternative cannot produce at all.
- *Two RQ2 arrays split by `--kinds`.* Costs one more job id to track; buys the
  oracle and bipartite work starting immediately instead of queuing behind the
  matrices job.

**Assumptions I proceeded on (each messaged or recorded):**
- The gate targets of `DESIGN.md` §2 (`0.188 / 0.211 / 0.300`) map to the corpora
  **in the order the section lists them** -- `synthetic_rq1`, `ndc_classes`,
  `wd50k66`. The design gives three numbers and three corpora but no explicit
  pairing. If the pairing is wrong the gate table mislabels which corpus missed;
  the measured medians themselves are unaffected. Recorded in
  `analyze_rq1.GATE_FACT_RANK` next to the assumption.
- "Extension cells, fact arms only" means the pointer arm is excluded and both
  `fact_rank` and `nauty_cert` run there. `nauty_cert` is not an alphabet, but it
  is cheap and its absence would leave the extension without a comparison.
- The `isalhg.*` package resolves on Picasso to the **shared** `IsalHG-tkde`
  checkout, not to my deployment, because the editable install is a PEP 660
  meta-path finder that runs ahead of `PYTHONPATH`. This is safe here only
  because `diff -rq` shows the two `src/` trees are byte-identical, which is what
  the prompt asserts for this wave. **It also means `common.sh`'s comment that
  `PYTHONPATH` ahead of the `.pth` entry keeps both halves on one tree is wrong
  for this install layout** -- reported to `main`, not fixed (not my file).

**Open questions for the orchestrator:**
- `single_edits(record, "add_constant", ...)` returned records with `n`
  unchanged and `constant_set_preserved = True` on `ndc_classes` (measured on
  `col.records[0]`, n=11). If `add_constant` is meant to change the constant set,
  the RQ1 regime column for that edit kind is mislabelled at the source. This is
  `datasets/kb/ladders.py` (owned by `kb-corpora`), so I recorded it rather than
  touching it. Everything downstream reports whatever the generator stamps.

## 10. Risks and follow-ups
